# App Proxy Bridge 设计与实施记录

## 目标与边界

根据用户后续决定，本项目改用 GPTProxyBridge 的用户态本地 HTTP 桥接方式：目标软件须自行遵循环境变量或启动参数。不再以 WinDivert 或自建 WFP 驱动作为当前版本的实现路径。产品不修改系统代理、DNS 或默认路由，不声称全流量代理或持续防直连。

默认所有软件共用一个本地入口与当前共享上游；软件可按需启用独立入口并绑定单独的上游。各入口属于同一桌面进程；应用上游更新只影响该入口的新连接，已建立连接保留原版本。独立入口首次绑定系统分配端口并持久化，恢复时若被占用明确失败；改变目标软件使用的入口后通常需要重新启动目标软件。

## 界面与交互

- 参考本项目《前端设计理念与原则》及 GPTProxyBridge：中性色、左侧导航、紧凑表单、浅色/深色/系统主题、状态文字和固定操作区。
- 软件、代理配置及设置各有独立页面；软件分共享和独立代理，代理表单区分未保存、已保存和实际应用。
- 目标程序只选择存在的 EXE，显式选择通用环境变量或加 Chromium 参数；程序不自动声称兼容。工作目录和每行一个启动参数放在高级设置。
- 测试使用当前编辑输入，应用前重新测试；上游失败保留旧生效配置。关闭窗口收至托盘，不自动结束目标程序。

## 看板增量：2026-10-30

- 根据用户确认，看板作为默认首页，以拓扑展示软件、本地入口和代理配置；点击节点查看详情并跳转原页面，最近错误仅在本次运行保存在内存中。
- 软件至入口的虚线表示已保存配置关系；入口至代理的实线只表示入口当前生效版本。连接数包含正在建立的连接，不能判断共享入口中连接所属软件。已保存版本变更、旧连接和上游错误分别显示，不将单次连接错误写成整个入口停止。
- 入口监听发生异常时标为异常并保留安全概括的错误，密码、请求内容和目标地址不进入看板错误记录；错误记录最多保留 100 条，每个入口详情展示最近 3 条，退出即清空。
- Release 构建零警告、零错误；本次运行 41 项核心回归与 16 项隔离 WPF 检查通过。覆盖监听异常及恢复、错误隔离与脱敏、共享/独立关系、待应用、停止、连接数口径、节点跳转、空状态与 28 个软件的滚动布局。使用本机模拟入口和临时配置，没有启动用户实际软件。
- 人工查看了模拟数据下的浅色、深色、空看板和长列表离屏截图。仍未完成真实目标软件流量、现场键盘/屏幕阅读器、高 DPI、托盘及干净机器验收；离屏截图和模拟测试不代表这些场景通过。


## 界面精修：2026-10-30

- 目标是保持 GPTProxyBridge 的紧凑中性风格，统一标题、表单、操作和状态，不改变用户态代理的产品边界。软件与代理配置页两列使用相同的 36 DIP 标题行、18 DIP 字号与字重；设置和看板也采用同高标题。将编辑与入口操作分组，保持最小内容区按钮同排，表单空间不足时允许滚动。
- 空选中时提示选择已有对象；测试状态区紧邻连接操作，区分未测试、配置改动后的重新测试以及测试中。顶部共享状态补充独立入口运行数量，没有运行入口时禁用停止全部。看板选中节点高亮关联连线；虚线与实线仍分别代表已保存关系和实际生效上游。
- 给列表项及下拉框提供明确的无障碍名称，修正深色展开标题及滚动条的主题显示；保留密码控件、证书校验、监听地址和连接切换逻辑。
- 执行者自查：Release 构建与自包含预览构建成功；41 项核心检查、27 项隔离 WPF 检查通过，包括标题上沿、字号字重、最小内容区按钮对齐、列表名称、独立入口与看板高亮。检查使用临时数据、本机模拟入口及目标测试进程。

## 退出时未保存草稿提示：2026-10-30
